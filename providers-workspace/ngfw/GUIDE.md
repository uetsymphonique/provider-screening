# NGFW (Next-Generation Firewall) Screening - Research Guide

Shared machinery lives in the
[`provider-assessment`](../.claude/skills/provider-assessment/GUIDE.md) skill:
verdict contract (rules 1–8), workflow, batch runner, source-type taxonomy,
staging/citation etiquette, grounding check, and pitfalls all live there and
apply to this domain verbatim. **This file only covers what is NGFW-specific.**

## Domain specifics

- **Provider list:** `providers/NGFW.csv` (1 vendor so far - this domain was
  added to test the provider-assessment pipeline end-to-end, not as a
  complete market survey; add rows as more vendors are scoped in).
- **Checklist:** 28 items across 6 categories; version pinned in
  `checklist.yaml` → `meta.version`. Machine-readable source of truth is
  `checklist.yaml`; `checklist.md` is the human-readable wording source.
  Written vendor-neutral against general NGFW market criteria (App-ID,
  IPS/sandboxing, SSL inspection, VPN/ZTNA, HA/throughput, management/
  compliance) - cross-checked against public NGFW buyer's-guide criteria, not
  copied from any single vendor's datasheet, even though `providers-workspace/ngfw/vNGFW.md` (a
  vendor datasheet staged locally) was used as one seed input.
- **Output:** `<this folder>/comparison_matrix.xlsx` (multi-sheet) produced by
  the shared `aggregate_matrix.py`.

## Per-domain files

```
ngfw/
├── checklist.md            # human-readable wording (source of truth)
├── checklist.yaml          # machine-readable IDs, verdict_type, thresholds
├── GUIDE.md                # this file
├── vNGFW.md                 # a vendor datasheet used as one input while drafting the checklist (not evidence for any assessment)
├── runs/                   # one subdir per product (see shared GUIDE)
└── comparison_matrix.xlsx  # generated by aggregate_matrix.py --domain ngfw
```

Everything else - `schemas/`, `templates/`, `prompts/`, `scripts/` - is
shared in `.claude/skills/provider-assessment/` and selected with `--domain`.
The aggregation entry point lives at
`.claude/skills/provider-assessment/scripts/aggregate/aggregate_matrix.py`.

## Workflow (this domain)

```bash
# 1. Kick off deep-research skill per product, writing to ngfw/runs/<product_id>/

# 2. Validate
python .claude/skills/provider-assessment/scripts/validate_assessment.py \
    --domain ngfw \
    ngfw/runs/<product_id>/assessment.json \
    --evidence-store ngfw/runs/<product_id>

# 3. Render report.md's mechanical sections (narrative preserved on re-run)
python .claude/skills/provider-assessment/scripts/render_report.py \
    --domain ngfw \
    ngfw/runs/<product_id>/assessment.json

# 4. Aggregate all validated products
python .claude/skills/provider-assessment/scripts/aggregate/aggregate_matrix.py --domain ngfw

# 5. Filter to deep-mode results if desired
python .claude/skills/provider-assessment/scripts/aggregate/aggregate_matrix.py --domain ngfw --mode deep
```

## Batch runner (this domain)

**Always pass `--domain ngfw`** - required, and there's no default to fall back to.

```bash
venv/Scripts/python.exe scripts/batch/run_batch.py claude --domain ngfw --mode standard --dry-run --skip-done
venv/Scripts/python.exe scripts/batch/run_batch.py claude --domain ngfw --mode standard --only axgate-ngfw
```

Global summary + total cost dumped to `providers-workspace/ngfw/runs/_batch/summary-<ts>.json`.

`--domain` and `--mode` are required for `run_batch.py` (argparse error if
omitted), along with the agent subcommand (`claude` or `pi`).
`tools/pdfstage/main.py`/`tools/htmlstage/main.py --domain` silently default to
`microsegmentation`'s tree if you forget it - always pass `--domain ngfw` for
this project.

See the shared GUIDE for staging, citation grounding, and pitfalls.

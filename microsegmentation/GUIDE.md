# Microsegmentation Screening — Research Guide

Shared machinery lives in the
[`provider-assessment`](../.claude/skills/provider-assessment/GUIDE.md) skill:
verdict contract (rules 1–8), workflow, batch runner, source-type taxonomy,
staging/citation etiquette, grounding check, and pitfalls all live there and
apply to this domain verbatim. **This file only covers what is
microsegmentation-specific.**

The project uses the [`deep-research`](../.claude/skills/deep-research/) skill
for per-product investigation but **replaces its default report contract** with
a structured, comparable one so 50 vendors can be aggregated into a single
matrix.

## Domain specifics

- **Provider list:** `providers/Microsegmentation.csv` (50 vendors).
- **Checklist:** 33 items across 8 categories; version pinned in
  `checklist.yaml` → `meta.version`. Machine-readable source of truth is
  `checklist.yaml`; `checklist.md` is the human-readable wording source.
- **Output:** `<this folder>/comparison_matrix.xlsx` (multi-sheet) produced by
  the shared `aggregate_matrix.py`.
- **Product-class context:** none — microsegmentation products (agent-based and
  network-based) are scored on the same checklist; `not_applicable` is still
  governed by rule 7 (item grammar), never by product class. Agent-property
  items are common enough that `checklist.yaml` tags both `mechanism` and
  `outcome` classes.

## Per-domain files

```
microsegmentation/
├── checklist.md            # human-readable wording (source of truth)
├── checklist.yaml          # machine-readable IDs, verdict_type, thresholds
├── GUIDE.md                # this file
├── runs/                   # one subdir per product (see shared GUIDE)
└── comparison_matrix.xlsx  # generated by aggregate_matrix.py --domain microsegmentation
```

Everything else — `schemas/`, `templates/`, `prompts/`, `scripts/` — is
shared in `.claude/skills/provider-assessment/` and selected with `--domain`.
The aggregation entry point lives at
`.claude/skills/provider-assessment/scripts/aggregate/aggregate_matrix.py`.

## Workflow (this domain)

```bash
# 1. Kick off deep-research skill per product, writing to microsegmentation/runs/<product_id>/

# 2. Validate
python .claude/skills/provider-assessment/scripts/validate_assessment.py \
    --domain microsegmentation \
    microsegmentation/runs/<product_id>/assessment.json \
    --evidence-store microsegmentation/runs/<product_id>

# 3. Render report.md's mechanical sections (narrative preserved on re-run)
python .claude/skills/provider-assessment/scripts/render_report.py \
    --domain microsegmentation \
    microsegmentation/runs/<product_id>/assessment.json

# 4. Aggregate all validated products
python .claude/skills/provider-assessment/scripts/aggregate/aggregate_matrix.py --domain microsegmentation

# 5. Filter to deep-mode results if desired
python .claude/skills/provider-assessment/scripts/aggregate/aggregate_matrix.py --domain microsegmentation --mode deep
```

## Batch runner (this domain)

```bash
# --- Standard pass (all vendors from Microsegmentation.csv) ---
venv/Scripts/python.exe scripts/run_batch.py --domain microsegmentation --mode standard --dry-run --skip-done
venv/Scripts/python.exe scripts/run_batch.py --domain microsegmentation --mode standard --skip-done --limit 3
venv/Scripts/python.exe scripts/run_batch.py --domain microsegmentation --mode standard --only illumio-core

# Resume after interruption
venv/Scripts/python.exe scripts/run_batch.py --domain microsegmentation --mode standard \
    --start-at cato-sase-cloud --skip-done
```

Global summary + total cost dumped to `microsegmentation/runs/_batch/summary-<ts>.json`.

`--domain` and `--mode` are required for `run_batch.py`; `pdf_to_text.py` /
`html_to_text.py --domain` silently default to `microsegmentation`'s tree, so
for THIS domain omitting it is fine — but always pass it explicitly to be safe.

See the shared GUIDE for staging, citation grounding, and pitfalls.
